# AI Brain Enterprise Platform（企业级多智能体协商决策平台）项目企划书

## 一、项目背景

当前主流 AI 存在单模型局限性，不同模型各有所长：

| AI | 优势 |
|---|---|
| ChatGPT | 系统规划、架构设计 |
| Gemini | 信息检索、知识整合 |
| Copilot | 软件开发、代码生成 |
| Grok | 创新思维、商业分析 |
| Muse | 任务执行、远程操作 |

任何单一模型都无法在复杂项目中同时达到最优效果。因此需要构建一个**多 AI 协商决策平台**，
通过多个 AI 共同讨论、互相补充、交叉验证，提高答案质量与决策可靠性。

## 二、项目目标

建立一个能够调度多个 AI、自动组织讨论、自动分析差异、自动生成下一轮问题、
自动形成统一结论、记录长期记忆、管理项目知识库的平台。最终形成**企业级 AI 数字董事会**。

## 三、核心理念

传统模式：用户 → AI → 答案

本项目模式：用户 →（平台编排）→ ChatGPT / Gemini / Copilot / Grok / Muse
→ 讨论 → 交叉验证 → 统一结论 → 最终答案

## 四、角色体系设计

- **平台（总控）**：任务管理、流程调度、讨论组织、历史记忆。权限最高。
- **ChatGPT（首席架构师）**：系统架构、产品规划、数据结构、流程设计。
- **Gemini（首席研究员）**：行业研究、竞争分析、法规政策、数据整理。
- **Copilot（首席开发工程师）**：代码生成、Bug 修复、自动重构、自动测试。
- **Grok（创新顾问）**：创新功能、商业模式、用户增长、新方向探索。
- **Muse（任务执行官）**：任务执行、远程操作、流程调度、历史记忆。

> 角色、专长、网页地址均可在「Agent 中心」修改，停用后不再参与新议题。

## 五、系统架构

```
用户层     Web（本阶段） / Android / Desktop / Browser Extension（后期）
协调层     平台 Orchestrator：任务分发、流程控制、结果汇总
AI 层      ChatGPT / Gemini / Copilot / Grok / Muse（网页版）
分析层     Difference Analyzer（差异提取） / Consensus Builder（共识生成）
知识层     Knowledge Base / Memory DB / Project DB（本阶段：本机 localStorage）
```

## 六、零 API Key 工作原理（第一阶段）

不依赖任何 API Key 能做到的上限是**人工中转**，这是诚实且可用的起点：

1. 平台按 Agent 角色生成提问（首轮为完整议题简报 + 角色视角指令）；
2. 用户复制提问，到各 AI 网页粘贴提问；
3. 用户把各 AI 的回答粘贴回平台；
4. 平台在本地做启发式差异分析（语义相似度聚类 → 共识点 / 独特观点 / 盲区）；
5. 平台按分析结果生成下一轮定向追问（最多 5 轮，可配置）；
6. 生成共识报告（Markdown），可复制、存入知识库、导出。

Transport 抽象已预留：`ManualTransport`（当前）/ `ApiTransport`（第二阶段 BYOK，直连 API）/
`ExtensionTransport`（浏览器插件半自动读写已登录 AI 网页）。

## 七、讨论机制

- 第一轮：原始问题 + 背景 + 约束，平台分发给所有启用的 Agent；
- 第二轮起：收集回答 → 提取共同观点 / 不同观点 / 遗漏观点 → 生成补充追问；
- 最后一轮后：生成统一方案（共识报告）；
- 最大讨论轮数：默认 5 轮（设置中可调 2~8），避免死循环。

## 八、主要模块（第一阶段 MVP）

- Dashboard：项目控制台（数据统计、工作原理说明、最近议题）
- 议题：发起议题、讨论室（多轮问答、差异分析、追问、共识报告）
- Agent Center：AI 管理中心（5 个默认 Agent，可编辑/停用）
- Knowledge Center：知识中心（共识报告、手动笔记、搜索）
- 设置：数据导出/导入/清空、最大轮数、API 接入预留（BYOK，第二阶段）

## 九、数据库设计（逻辑）

users（后期）/ projects（议题）/ discussions（轮次问答）/ agents（Agent 配置）/
memories（长期记忆）/ tasks（任务记录）/ reports（生成报告）

> 第一阶段全部落在本机 localStorage（key：`aibrain.v1`），导出为 JSON 备份；
> 第二阶段迁移到 PostgreSQL / Supabase。

## 十、技术架构

- 第一阶段：纯静态 Web（HTML/CSS/JS，无构建），GitHub Pages 托管，零后端、零 Key
- 第二阶段：Node.js + Express 后端，PostgreSQL / Supabase，Redis 缓存，BYOK 接入各模型 API
- 第三阶段：自动创建 GitHub Issue、自动生成代码、自动提交 PR、自动测试（AI 软件开发团队）
- 第四阶段：物流行业 Agent 扩展（物流/海关/运价/仓储/客服/财务/风控）

## 十一、商业价值

适用于：软件公司、国际物流公司、电商企业、AI 创业团队、咨询公司。

## 十二、最终愿景

打造"多个 AI 协商、学习、分析、执行的数字企业大脑"，
从回答问题升级为自主规划、自主分析、自主协作、自主执行的企业级智能运营平台。

## 十三、诚实说明

- 没有 API Key 就无法真正"自动"调用各模型：第一阶段的"自动组织讨论"指平台自动生成
  提问/追问/分析/报告，**提问与回答的搬运由人工完成**，约 2~3 分钟一轮。
- 本地启发式差异分析是语义相似度聚类，仅供辅助判断，最终结论由人工确认。
- 各 AI 网页需要用户自己登录；回答质量取决于各模型的网页版能力。
